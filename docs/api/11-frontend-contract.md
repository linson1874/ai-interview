## 🔶1. 项目结构：src 下怎么切
目录树你画。必答三问：① API 调用层按后端合同分文件还是按页面分？（提示：01/03/06/07/09/10 六域）② 全局状态（token/用户信息）放哪、活过刷新吗？——这个决定连着 02 合同的存根生命周期，写进你的论证；③ F2 错误码映射表住哪个文件、为什么住那。

## 🔶2. 请求层设计（axios 拦截器，必须手写）
本节文件=学员手写范围（#75 底线件一）。骨架已钉的家法：401→清态跳登录（F6）；非 0 code→查映射表弹文案（F2）；网络层错误→统一"服务繁忙"兜底。
你亲手补三处：① token 的存放与注入方案（论证：localStorage 与内存的取舍，对着"票面可复制"的既有认知说实话）；② 请求失败的 toast 与业务错误的 toast 要不要同一通道（一句话理由）；③ **页面级 loading 的默认策略**——每个组件自管还是请求层统一计数（08 空手降级案的 UX 镜像）。

## 🔶3. 轮询原语（本合同的灵魂页）
本节文件=学员手写范围（#75 底线件二）。F4 三态机的通用化：你要设计**一个**可复用的轮询 hook（interview status / reportStatus / review due 三处复用同一个）。
拍板并论证：① 间隔策略（恒定 3s？退避？上限？）；② 组件卸载/路由切换时的中止语义（fetch 取消还是忽略回调，给理由）；③ 连续 N 次失败的熔断 UX（一直转圈是骗人，直接报错可能误伤——07②门案的后端版）；④ 页面可见性（切标签页暂停？document.visibilitychange）。
**这一节写好，全项目的前端含金量都在这里。**
