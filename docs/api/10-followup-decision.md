## 0. 一句话产品定义

真实面试官不会问完就过——答得好往深挖，答得差换角度再验，直到摸到能力边界。本模块把这条"追问树"装进面试会话：以已答题为根，按信号驱动最多两层追问，产出"深挖轨迹"进报告叙述。

## 1. v1 范围纪律（先划死不做的事，再谈要做的）

| 做 | 不做（留档立项） |
|---|---|
| 两层追问树 + 信号驱动分支 | 在线重选题（主卷答完再抽下一题——需重构 06 面试流，规模未到不付这钱） |
| 追问与 09 复习队列联动 | Elo/Rasch 能力值建模（校准题库才配谈测量，我们只有标签没有大样本） |

| 追问生成 prompt 学员初稿 | 实时中断/续面（会话形态大改，秋招后的产品迭代议题） |

## 2. 决策点

### 🔶A 端点形态与契约影响分析（CIA，09-C 之后第二次正式动作）
候选：(a) 独立端点 `POST /interview/{id}/followup/{qid}`——06/07 零行为变化；(b) 答题端点自动扩展——07 升版、既有回归网全重跑。
**交表**：每个候选对 06（会话状态机/题表）、07（answer 语义/报告口径）、09（队列联动钩子）的冲击面逐格填。附带必答：追问端点允许的运行态——status=1 进行中可追，**finish 之后追？口径是 404 三态还是 code=1"已交卷"？**（两个都对，但只能选一个写进合同，另一个进面试话术"我为什么选它"。）

### 🔶B 决策状态机（本合同的灵魂，规则每条附信号质量论证）
输入信号现成：score 0-5（07 口径）+ 09 的 promote/demote/freeze 语义可复用。骨架规则（可调，调了要论证）：
```
score≥4 → 下钻一层（更深/更边界，同方向加压）
score=3 → 不钻深，换角度同层验证（半懂最会骗人，3分冻结原则的追问版：
          不奖励也不惩罚噪声，只多要一个证据）
score≤2 → 降级脚手架追问（拆小问题定位断点在哪层）+ 该题入 09 复习队列（联动钩子，X8）
深度上限=2（到顶必停，无论答什么）
```
你的活：① 认/改这四条边，每条给论证；② **答一道开放题：追问的"答"要不要驱动第二次追问的分叉，还是追问树一次性出完？**（一次性=会话简单不可变；分叉=真面试官但状态复杂——06 状态机与 09 幂等思想在这里第三次服役，说清你借鉴哪个原型。）

### 🔶C 追问来源：题池优先还是 LLM 现编
(a) 从 08 题池按 (tags ∩ 原题方向, difficulty+1) 检索选追问——零 AI 成本、可审计、但贴合度粗；(b) LLM 现编——贴简历贴上下文，贵 + 格式事故面扩张；(c) **题池优先、检索空手降级 LLM 现编**——材料三级阶梯模式第三次复用。
拍板并写明选 (c) 时"降级必须标注"的语义（标注给谁看？报告还是日志？——09-A 的诚实降级哲学延伸）。

### 🔶D 数据形状与报告口径（样本闸第二战）
追问落哪：t_interview_question 加 `parent_question_id`（sql/09 增量，全局第 9 份/MySQL 第 7 份，数法自己数对）vs 独立 t_followup 表。
**硬约束（不可谈判项预写）**：追问成绩**不进** overall——聚合 SQL 加 `parent_question_id IS NULL` 物理排除，X6 用断言前后一致来守。报告叙述可含"对 X 题追问两层，深度第 2 层得分 Y"。附答：追问要不要进 weakPoints/evidence（它算不算"该补什么"的证据？）——两轴聚合（09-D）会不会被追问污染，想清楚。

### 🔶E 成本护栏
per-场追问总量上限（如 ≤6 发）、per-端点模型调用数（生成 1 + 评分 1？评分直接复用 07 链）、max_tokens 预算（按 05/07 的"分布上沿×1.2"老公式算，我要看到算式）、全部进 application.yml 新节 followup.*（旋钮进 Git，AGENTS 家法）。usage 回显进响应（S1 model 回显衣钵）。

### 🔶F 追问生成 prompt 初稿——**你的毕业作业**
这二十天你收了九份"逐字件定稿"，今天轮到你交一份：追问生成 system prompt（角色、与原题/简历的锚定要求、深度语义（下钻/换角度/降档三种指令如何区分）、输出 schema（JSON、字段枚举、禁解释文字——J5 纪律）、candidate_answer 定界若答案入 prompt）。
**流程**：你出初稿 → 导师逐字评审（#16 仪式，这次你是被评审方）→ 定稿入 10 §4。**评审会看四样**：规则间打不打架（F1 式）、有没有给模型留"自己加戏"的口子（规则1vs3案）、token 预算写没写死（S14 案）、注入面防没防（E3 案）。
