## 1. 接口：生成面试题 `POST /ai/questions`

### 1.1 请求（GenerateDTO）

| 字段 | 必填 | 校验 | 失败文案 |

| resumeId | 是 | @NotNull | 请指定简历ID |

### 1.2 错误语义全景（学员 Q1b 两错分离表采纳 + 导师补全）

| 场景 | HTTP | code | msg | 出处 |
|---|---|---|---|---|
| 缺 resumeId / count 越界 | 200 | 2 | §1.1 | @Valid 门口拦截，**不发 SQL**（学员） |

| 未登录 | 401 | 3 | 继承合同 02 | — |

## 2. 题数与成本护栏（学员 Q2 三分法采纳，数字经 R5 修正）

- 上限 5 依据（学员）：① 成本非瓶颈（满配厘级），设上限是让**失控线可见**（count=1000≈4元/次，不设限=把计费器交给用户的手）；② **时长才是同步模式真约束**，60s 预算倒推 5 题；放宽到 10 的解锁条件=流式改造（阶段三）；③ 产品常识：应届模拟面单场 5 题。
- R5 修正后的输入估算：real_name 32 + target_job 64 + education 64 + skills 1024 + self_intro 1000 ≈ 2184 字符，按 1字≈1token 保守计 ≈ 2.5k + 指令/schema 0.5k → **prompt ≈ 3k tokens**（原稿 `experience 255 / education 255` 为幽灵字段，已纠；结论"钱不是瓶颈"不变）。
- 本端点 per-call `max_tokens=3000`（≈5题×500×1.2），与 /ai/chat 全局 512 **分离**（学员）；实现走 `OpenAiChatOptions` 请求级覆盖，不污染 yml。
- usage 实测回填：G1 首跑时在响应 usage 回显真实值并回填本节（学员承诺项）。**已兑现，见下**。

### 2.1 实测回填（2026-11-08 G1，@Disabled 冒烟测试，轻载：短简历+5题无refAnswer）

> 实测：**prompt=504 / completion=225 / model=deepseek-flash**，单次成本≈0.003 元（flash 高峰价）。
> ① 3k prompt 系"满字段最坏简历"上限口径，本次轻载未打到，上限结论不变；
> ② 500/题 系"含参考答案"口径，R3 去除 refAnswer 后实测 ~45/题——估算系数挂在输出形态上，决策改形态则数字重算；输出预算 3000 保留为失控护栏（~13x 余量）；
> ③ "钱不是瓶颈、同步时长才是"获实测确认；
> ④ **漂移实锤**：yml 配 deepseek-chat，元数据回显 deepseek-flash（官方旧名重映射）——配置已正名 flash；"model 从响应元数据取、不许自报家门"的可观测性价值由此案确立。

**导师复测注记（v1.1，2026-11-08 G1 全链路重跑）**：prompt=526 / completion=**1926**（≈385/题，长问法）。与学员冒烟的 225 差近一个数量级——**token 消耗是分布不是常数**，题面长短全看模型表达欲；3000 护栏利用率 64% 仍安全，但由此暴露真实链路：**模型话痨→撞 max_tokens→输出腰斩→JSON 不闭合→L2 救不了→L3 重试**——护栏本身就是畸形源之一，阶段三统计命中率时会见到它。§2 系数按"分布上沿"而非"冒烟点值"理解。

## 3. 格式失败三级策略（学员 Q4 原文，架构采纳）

```
L1 预防(请求前)：JSON mode(DeepSeek response-format=json_object, 服务端保证可parse)
                + getFormat() schema 指令注入
L2 清洗(解析时)：剥 ```json 围栏 / 截取 {} ——表象脏，不重问模型（官方 LenientJsonOutputConverter 思路）
L3 重试(仅一次)：字段级实质畸形才允许花第二次钱。
   原则（学员原话）：重试必须携带增量信息——原样重发是掷骰子（同prompt同温度=同分布，畸形概率几乎不变，白烧钱）
   方式：system 末尾追加纠错强化句："上一次输出包含非法内容。本次只输出一个符合 schema 的 JSON
        对象，禁止 markdown 代码块，禁止任何解释文字。"
   禁用：喂回脏文本的修复式（OutputFixing 思路）——会把模型的胡说二次注入上下文，记为阶段三进阶谈资
```

- 重试仅一次 + `log.warn` 留痕（学员：留痕观测 L2/L3 命中率——**天天重试=该修 prompt，不是加次数**）。
- 最终失败 `log.error` **必须带畸形原文全文**（学员：上游报错看堆栈，格式事故看原文；对外简答、对内可查的延续）。
- Converter 原理（学员答对入档）：`getFormat()` 返回**已渲染成品原文**，经 `{format}` 占位符或 `.entity()` 自动追加进 prompt——原文进模板，不是模板等填充。

## 4. 输出 schema（R3 导师代拍）

```json
{ "questions": [ { "category": "八股|项目|场景|HR", "difficulty": 1|2|3, "question": "……" } ] }
```
（上为**模型产出物**；接口 `data` 完整形状=questions + model + usage，model/usage 从响应元数据取，**不许让模型自报家门**——实现清单第 3 条的坑。）

- category 逐字对齐 `t_interview_question.category` COMMENT：八股/项目/场景/HR（学员）。
- **refAnswer 本版不要（R3：学员开放题未拍板，导师代拍）**：同步模式输出翻倍直接顶爆 §2 自定的 5 题时长预算；阶段三评分时"参考答案与评分标准同时按需生成"更省且口径一致。教训入档：**开放题不拍板，就会被别人替你拍。**

## 5. Prompt 工程（学员 Q5 成稿，R6 两处一致性修正）

三层分责（学员，采纳）：**语法层** JSON mode 只保证可 parse（它能吐 `{"foo":1}`）；**结构层** getFormat() 保证字段形状；**内容层** system prompt 管职业操守——三层各管一段，互不越权。

**system prompt 定稿：**
```
你是应届生技术面试环节的面试官，任务是根据候选人简历生成面试题。
规则：
1. 只生成面试题，不作答、不闲聊、不解释你的行为。
2. 每道题必须与简历内容相关；"项目"类题目必须引用简历中的具体经历，不许凭空编造简历里没有的项目。
3. category 只能取以下四个值之一：八股、项目、场景、HR；difficulty 取 1（简单）、2（中等）、3（困难）。
4. 题目难度需有梯度，禁止全部同档。
5. 题干使用中文。                                    ← R6：原稿此条含"参考答案"，与§4冲突，删
6. 只输出一个 JSON 对象，禁止输出任何解释文字、前后缀，禁止使用 markdown 代码块符号。
```

**user 模板定稿：**
```
候选人简历：
姓名：{realName}
目标岗位：{targetJob}
教育背景：{education}
专业技能：{skills 顿号拼接}
项目与自我介绍：{selfIntro}                          ← R6：原料=self_intro，不存在 experience 列
请生成 {count} 道题。
{format}
```

- 题数等运行时数字放 user 不放 system（学员：system 只写与题数无关的规则，模板可缓存复用）✅
- **skills 顿号形态四条论据（学员原文保留，本评审最佳段落）**：① 形态跟用途走——DB 存 JSON 串（无损可逆）/Java 用 List/prompt 用顿号（语义密度），三形态无通吃，是 DTO/VO 分层哲学在 prompt 侧的延伸；② `["..",".."]` 的括号引号是**付钱的噪音**，零语义照样计 token；③ 输入端塞 JSON 与输出端 JSON mode **格式信号打架**，是 L3 事故来源之一；④ 诚实边界：大模型吃 JSON 串也"能用"，这是"能用 vs 最优"不是对错题；顿号在技能名含标点时有歧义（极小概率，本版接受，写明权衡即加分）。
