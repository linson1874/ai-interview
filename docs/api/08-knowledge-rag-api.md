## 2. 决策点

### 🔶K1 容器与端口
`ai-pgvector`（镜像 `pgvector/pgvector:pg16` 已在本地缓存——那次彩蛋的回收日）。拍板：
a) 端口 **5432 还是 5433**？（`interview-postgres` 那个旧容器禁动但它的端口阴影还在——想清楚"我们是否要永久避开 5432"，给出你的理由）
b) 卷名、密码走 `-e`（不进 Git 老红线）；**新容器出厂自带 `TZ=Asia/Shanghai`**（R9 时钟单源纪律第一次在新容器上的主动执行——别等第二次 qid61 案）。

### 🔶K2 双数据源接线（本课墙一，先调研再拍）
Boot 检测到第二个 DataSource 会**罢工自动配置**。方案光谱：
- a) 手工双 Bean：MySQL `@Primary`（喂 MP），PG DataSource 专供向量层（Hikari 自建 + JdbcTemplate/Dao）
- b) PG 侧不用 DataSource Bean，走 pgjdbc `PGSimpleDataSource` 私有对象
- c) dynamic-datasource 全家桶（**过度设计，写出来给我看看你为什么排除它**）
拍板：选哪个+PG 连接参数放哪个配置文件（提示：`application-dev.yml` 的 `spring.datasource` 已被 MySQL 占用）。另答一问：**MySQL 和 PG 之间需要事务一致性吗？**（答"要"的先想清楚要在哪一步——这题答对省你三天弯路。）

### 🔶K3 embedding 选型（本课第一次多厂商动真格）
DeepSeek 无 embedding 接口——#10 你们自己预言的"多 key 并存"落地日。候选：
- a) 百炼 `text-embedding-v3/v4`（OpenAI 兼容 embeddings、1024 维、价格查当日牌价——**调研义务：报数字**）
- b) 本地开源模型（bge 类，经 ollama 或纯 Java 推理）——token 零费换内存/延迟成本
- c) 其他你在文档里发现的第三方
拍板表格式：单价×题池规模=一次性成本；查询侧每场面试调用数×单价=运行成本；延迟预算。**环境变量名沿用 R10 口径（厂商前缀合法）：`BAILIAN_API_KEY` 与 `DEEPSEEK_API_KEY` 并存。** 维度必须与表 schema 锁死（写进 K4）。

### 🔶K4 题池 schema 与审核流（本课墙二：PgVectorStore 托管 vs 自建）
两条实现路线：
- **托管**：Spring AI `PgVectorStore`（自带 schema：id/content/metadata/embedding，跑初始化 DDL）+ SimpleraritySearch 全家桶——省事，但**元数据是弱类型 Map**，"审核状态"这种业务字段靠约定
- **自建**：自己的表（建议列：content/category/difficulty/status(draft→pending→approved→retired)/source/embedding vector(N)/embedding_model/时间戳）+ HNSW 或 ivfflat 索引（**拍板二选一并给理由**）+ 手写相似度 SQL
拍板：路线、表名、维度（=K3）、索引类型、以及**审核状态机**——重点答：**运行时检索必须只命中 approved，这条硬约束写在哪一层？**（提示：这就是 RAG 投毒的第一道闸；写漏一层=把审核制变成装饰品）
入库管线（本版本）：离线脚本批量灌样题（生成走现有 LLM+人工改稿标记 approved），**不做管理 HTTP 端点**（K7 解释为什么这是安全而非偷懒）。

### 🔶K5 检索参数与出处
topK=？阈值=？过滤=category+difficulty 元数据先行还是纯向量？——拍板并**全部做成配置**（不许硬编码，理由：调检索参数是日常调参不是发版）。
**出处回显**：RAG 化的出题接口返回 `evidenceKbIds`（引用了题池哪些条目）——延续 05 model/usage 可观测衣钵：AI 的回答要能考古。

### 🔶K6 RAG 接到哪一端（本课的产品判断）
候选：a) 出题链（检索相似题→模型改编/参照生成，题题有出处）；b) 评分链（八股题给评分器递知识库标准答案=J4 测量口径的第一步）；c) 两端都做；d) 本阶段只做"知识库问答端点"（新 `/ai/kb/ask`，独立最小链，出题评分链暂不动）。
**推荐你认真考虑 d 作起点**（理由要你写：改动面/回滚成本/05 和 07 合同要不要跟着升版）——但反推荐也可以，带论证来。

### 🔶K7 权限面（今天最小，把债记清）
题池审核脚本谁能跑？（现在=运维本人/学员本机，无 HTTP 面=无攻击面——这就是"不做管理端点是安全设计"的完整句子）。**若**你 K6 选了含端点方案涉及写操作：权限模型三选一（白名单 userId 配置/`t_user` 加 role 列+拦截/推迟）——且注意 **403 错误码还不存在于 01 文档表**，引入即触发新一轮契约变更（错误码"禁止私加"的家法你还记得）。
