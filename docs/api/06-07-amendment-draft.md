## 2. 增补二：`POST /interview/{id}/cancel`（取消未就绪场次）

### 2.1 #48 已批方向（复述，不再讨论）
归属+未就绪**原子**作废；重复取消幂等；迟到结果丢弃；出题提交与状态条件同一事务；outbox/补偿天然跳过作废场次。

### 2.2 状态机（导师预判版，🔶e/🔶f 拍板）

```
             ┌───────── CAS(0→4) ─────────┐
             │                            ▼
   [0 排队] ─┴─ [4 生成中] ──CAS(4→1)──▶ [1 进行中] ──finish──▶ [2 已交卷]
      │           │                        │
      │           │ CAS(4→1)失败且评分炸   │
      │           ▼                        ▼
      │        [3 失败] ──retry(CAS 3→0) 回 [0]
      │
      └── cancel? ──▶ [5 已取消] ◀── cancel? ──┘（🔶e：合法入边拍板）
                         │
             outbox 扫 status=0 ？  消费者 CAS 认 5 ？
```

> **🔶e 合法入边拍板**：导师预判=**仅 {0, 4}**。论证义务：① `1 进行中` 为什么不可取消（题目已就绪，用户的出口是作答/交卷，取消=把"考了一半"变成什么状态？没有合理终态）；② `3 失败` 为什么不设 cancel（retry 域={3} 已实查，两接口抢一个状态域=两套语义打架；不想重试的用户让它在列表里躺着就行）；③ `2` 不可（流程已终结）。**不同意预判就反驳，给出你的域和理由——反驳成立照例记功。**
>
> **✅ 拍板（🔶e）**：同意预判，合法入边=**{0, 4}**，反驳不成立。三条义务照交：① `1` 不可取消——题目已就绪，出口是作答/交卷；取消找不到合理终态：不算 2（没交卷）、不算 3（不是失败）、若算 5 则"答了一半"与"没开考"共用语义，报告复盘口径全乱——#48 把 cancel 限定在"未就绪"是对的。② `3` 不设 cancel——retry 域={3} 已实查，cancel 若也认 3，两接口在同一状态域上各 CAS 各的，并发互踩语义打架；不想重试的用户让它在列表里躺着（徽章"失败"），损失为零。③ `2` 流程已终结，cancel 无对象。

> **🔶f 新状态值拍板**：`5=已取消`（TINYINT 追员）。确认值号与语义名。
>
> **✅ 拍板（🔶f）**：确认 `5=已取消`。0~4 实查未被占用，5 追员合法；语义名"已取消"，DDL COMMENT 增补随 §5 提交（连带补 4）。

### 2.3 免疫论证表（§2.4 学员必答作业——判词原话："这是'改数据结构让需求消失'的验收标准"）

| 既有机制 | 它现在认什么 | 为何**一行不改**就跳过 5=已取消 |
|---|---|---|
| outbox 补投（60s 扫描） | status=0 且 stale | 补投扫描的 WHERE 只认 `status=0`，cancel 与归属校验同一条 update 把 0 改成 5——扫描条件对已取消行**恒不命中**，免疫靠既有条件天然不满足，不是靠加新分支 |
| 消费者抢单 CAS | IN(0,4) → 4 | 抢单 CAS 前置集 `IN(0,4)` 不含 5，取消后消费者 CAS 必然 0 行命中，走既有"0 行=放弃该消息"路径静默退出——零新分支 |
| 消费者完成回写 | CAS 4→1 | 完成回写是 CAS `4→1`，取消已把行改成 5，CAS 不命中→回写整体丢弃、题目不落库（即 C3 正证）。诚实边界：取消发生在生成途中时，这次生成的 AI token 成本已花且不追回——cancel 是免费的"状态作废"，不是免费的"算力退款" |

### 2.4 其余决策

> **🔶g 幂等语义拍板**：对已是 5 的场次再次 cancel → 候选 A：幂等成功 code=0（"取消"语义天然幂等，删除接口先例：D7 一律 code=0）；候选 B：code=1"已取消"。给一句理由。
> 对 `2 已交卷` cancel → code=1"本场已交卷，无法取消"（HTTP 200 业务码，家法：用户改不了输入结果的不给 4xx）。
> 他人场次/不存在 → **统一 404**（T8 家法：不泄存在性）。
>
> **✅ 拍板（🔶g）**：选候选 A——重复 cancel **幂等成功 code=0**。理由：cancel 的目标终态唯一（都是 5），双击/网络重试应与首调同结果；选 B 则前端必须区分"首次取消/重复取消"两条 success-adjacent 路径，纯增复杂度零收益，D7 删除接口先例照搬。其余两条照草案钉死：对 `2` cancel → code=1"本场已交卷，无法取消"；他人/不存在 → 统一 404。

> **🔶h 列表联动拍板**：5=已取消在列表页的徽章文案？从 5 能发起 retry 吗？（预判：不能——retry 域={3} 不扩；列表页对 5 的唯一动作="查看"（题目没生成出来，看什么？其实**看不了详情**→那 5 在列表点的行为是什么？这个 UX 问题你的页面卡必须回答）。
>
> **✅ 拍板（🔶h）**：徽章文案=**"已取消"**；从 5 不能发起 retry（retry 域={3} 不扩，C7=code=1"状态不符"）。UX 出路：**status=5 的列表行不可点入**——题目没落库，详情页无内容可渲染，伪跳转=404 假案；行点击对 5 直接 no-op，不放任何动作按钮。用户对已取消场次可见的信息=徽章"已取消"+ createTime，足够回答"这场怎么了"；若未来要展示取消原因，那是新列新合同，不进本包。

**实现注记**（v1.0 导师自纠版）：**两步归因，照 retry 同构**——①归属门先查（`selectOne eq(id).eq(userId)`，null → 统一 404，T8 家法）；②再条件 CAS（`in(status, {0,4})` → set status=5），affected rows=0 = 状态不符 code=1。v0.1 原文"单条 update 三态归因"内部矛盾（affected rows 区分不出三态），判词自纠；并发安全由 CAS 条件在写入时点复查保证，select 与 update 之间无竞态窗口。返回 `Result<Void>` msg=ok；**表单保留=前端职责**。
