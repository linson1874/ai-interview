## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | `http://localhost:8080` |
| 请求体格式 | `Content-Type: application/json` |
| 响应包装 | 一律为统一结构 `Result`：`{ code, msg, data }` |
| 成功判定 | `code = 0`（HTTP 状态仍为 200，业务成败看 code） |

### 错误码表（前后端约定的暗号，禁止私加）

| code | 含义 | 前端处理建议 |
|---|---|---|
| 0 | 成功 | 取 data |
| 1 | 业务失败（如用户名已存在） | 弹 msg |
| 2 | 参数校验失败 | 弹 msg（表单标红） |
| 3 | 未登录/凭证失效 | 跳登录页（预留，登录课启用） |
| 500 | 系统异常 | 弹"系统繁忙"，后台已记日志 |

## 2. 接口：用户注册 `POST /user/register`

### 2.1 请求参数（Body JSON）

| 字段 | 类型 | 必填 | 校验规则 | 校验失败提示 |
|---|---|---|---|---|
| username | string | 是 | 非空；长度 3–32 | "用户名不能为空" / "用户名长度3-32" |
| password | string | 是 | 非空；长度 6–32 | "密码不能为空" / "密码至少6位" |
| nickname | string | 否 | ≤32 | — |

### 2.2 业务规则（Service 层职责）

1. 查重：username 已存在（含逻辑删除过滤）→ 业务失败 code=1，msg="用户名已存在"
2. 密码**不得明文入库**：BCrypt 加密后存储（库中值应形如 `$2a$10$...`，60 位）
3. 新用户默认 `status=1`、`deleted=0`（deleted 由 DDL 默认值兜底）
4. 并发兜底：捕获 `DuplicateKeyException` → 同样返回 code=1（防两请求同时过查重）

### 2.3 响应示例

成功：
```json
{ "code": 0, "msg": "ok", "data": null }
```

用户名重复：
```json
{ "code": 1, "msg": "用户名已存在", "data": null }
```

密码过短：
```json
{ "code": 2, "msg": "密码至少6位", "data": null }
```

### 2.4 验收用例（测试即照此打勾）

| # | 场景 | 输入 | 期望 |
|---|---|---|---|
| A | 正常注册 | `{"username":"lisi_001","password":"123456","nickname":"李四"}` | code=0；库中新增 1 行，密码为 BCrypt 密文 |
| B | 重复注册 | 同 A 再发一次 | code=1, msg="用户名已存在"；**不产生新行** |
| C | 弱密码 | `{"username":"wangwu","password":"12"}` | code=2, msg="密码至少6位"；**不产生新行** |
| D | 空用户名 | `{"username":"","password":"123456"}` | code=2 |
