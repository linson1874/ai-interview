# 差异化设计提案 v0.1（待导师评审拍板，2026-11-06）

> 定位框架：市面系统都挤在"面试中：一次性出题+评分"。本项目的差异化押注在
> **①"面试中"的 agent 化（追问与难度自适应）** 与 **②"面试后"的提分闭环（遗忘曲线复现）**。
> 两个模块共用一个前提：每道评分都沉淀为**知识粒度的结构化信号**，而不是用完即弃的报告。

## 主打一：自适应面试官（Adaptive Interviewer）——"没有第二个系统敢当场追问你"

**痛点**：现有一切系统都是"问一题→评一题→下一题"的线性流水，而真实面试是**树状的**：答得好往深追，答得差换角度再验，直到探到能力边界。单轮问答的区分度天然低——背得到八股≠会。

**设计**：把一次面试做成**决策循环（agent 状态机）**：

```
出题 → 作答 → 即时评分(已有能力) → 决策器:
    ├─ 答对且置信 → 难度+1 或 换关联考点深挖一层(最多3层)
    ├─ 答对但答案有"背诵感"(语义特征) → 抛变体题/追"为什么这样设计"
    ├─ 答不出 → 降一级给脚手架题验证是真不会还是表达问题
    └─ 该考点方差收敛 → 换考点 / 全部收敛 → 结束出报告
```

**技术亮点（面试可讲的）**：
- 评分信号喂给**简化版 IRT/Elo**：每考点维护能力值，每道题标难度分（离线批量出题+模型预标难度），选题=挑"能力值±Δ"的题 → 这是**CAT 计算机自适应测验**的正统算法，教育测量学的东西出现在秋招项目里是降维打击；
- 追问链的状态管理 = 阶段三 Redis（Stream 消息 + Hash 存会话状态）的**天然深化**，不是加需求是加深度；
- 决策器先做**规则版**（上面那棵树），LLM 版（"评估该不该追"交给模型判断）做对照实验——两版对比就是论文式素材。

**MVP 边界（防过度设计）**：先做"单考点 3 层追问 + 难度升降"，Elo 全局量表后置；不做 ASR/数字人/多 agent 辩论那种名词堆砌。

## 主打二：提分闭环（Forgetting-Curve Review Loop）——"面试系统做完测评就下班，我们开始上班"

**痛点**：用户被评完"MySQL 索引 62 分"就结束了。**错的东西何时再见、见了没见、见了还错不错**——没有任何系统管。而这恰是刷题者最痛的"练了不巩固"。

**设计**：评分即写入**复习调度队列**：

```
答错的题+知识点 → 按遗忘曲线计算下次复现时间(D1/D3/D7/D16...)
Redis ZSET: key=review:user:{id}, member=题目id, score=下次到期时间戳
定时扫描到期 → 塞进下次面试的"开场热身3题" → 答对间隔翻倍/答错重置
数据产出: 每考点的"掌握度曲线"(时间序列) + 预计遗忘时间
```

**技术亮点**：
- Redis **ZSET 延迟队列**教科书级实战（和阶段三的 Stream 形成 Redis 两大武器库：流 + 有序集合）；
- 间隔重复算法（SM-2/Leitner）是真实存在、可讲清原理的算法——秋招项目里罕见；
- 与主打一天然咬合：追问探到的**薄弱点**正是复习队列的**优先级信号**。

**产品叙事**："别的系统给你分数，我的系统保证分数不再掉回去"——一句话讲完差异化，面试官记得住。

## 风险与克制声明
- 两个模块都**依赖评分质量**（阶段三地基打歪，这里全歪）——所以顺序不可颠倒；
- 题池冷启动靠"离线批量 LLM 生成+难度预标"，质量不够时先用简历锚定题过渡；
- 明确**不做**：数字人面试、多 agent 辩论评分、全功能"对标牛客"——差异化≠功能军备竞赛，是把两个别人没做的点做到能讲出算法名字。
